	This file gives simple instructions on how to create your first route, 
and how routes work in general. Routes are consisted of two parts in one folder,
all named the same thing: the .map file, and the .events file.

### .MAP FILE ###
This file contains the visible map used to traverse the land. It is often made
of ASCII art, and must contain a few %c statements so the game can print which
locations have been passed already. A very simple example is as so:


---------------------------------
|                               |
|  \---------------/        -\  |
|  |               \^/\  __/ |  |
|  |                | /_/  %c/   |
|  \                   %c  /     |
|   %c                    /      |
|    \%c_____%c      %c   _/       |
|           \_  /---^\ \        |
|             \/      \/        |
|                               |
---------------------------------
End


When being printed in the game, it will look something like this:
---------------------------------
|                               |
|  \---------------/        -\  |
|  |               \^/\  __/ |  |
|  |                | /_/  X/   |
|  \                   X   /    |
|   O                     /     |
|    \O_____O      X   _/       |
|           \_  /---^\ \        |
|             \/      \/        |
|                               |
---------------------------------

Using "End" at the end is NECESSARY for the program to recognize when to stop
reading the file. If it is not there, it will print that the map file is mis-
configured.

### .EVENTS FILE ###
The more complicated of the two, so starting with an example is needed:


25
1.5 2.5
1 1
6 1
12 3 2
Hunter
Nobody
This is a test string. If you're seeing this, it worked.


This is an example of a single event, a .events file needs six of them. To break
it down further:

TS
C1CM C1OM
C2CM C2OM
IA IT
OAG OAB OT
Char1
Char2
String

1	TS: 	The minimum threshold needed to complete the event. Not 
		displayed to the player. Out of 100.
2	C1CM:	Character 1 Chance Multiplier. Multiplier applied to TS (1) 
		value as correlating to Char1's (11) proficiency in the event's 
		scenario. A value from 0.5 to 2 ideally, but can be higher.
3	C1OM:	Character 1 Output Multiplier. Multiplier applied to OAG (8) or
		OAB (9) correlating to Char1's (11) proficiency in the event's
		scenario. A value from 0.2 to 3 ideally, but can be higher.
4	C2CM:	Same as C1CM (2), but for Char2 (12).
5	C2OM:	Same as C1OM (3), but for Char2 (12).
6	IA:	Input Amount.
7	IT:	Input Type. The type of value put into the event.
		0 = Health (not usual to be input)
		1 = Resources
		2 = Money
		Amount put in depends on what the type is.
8	OAG:	Output Amount Good. If player is above threshold, return this
		amount of value to them.
9	OAB:	Output Amount Bad. If player is below threshold, return this
		amount of value to them. Affected by C1OM (3)/C2OM (5).
10	OT:	Output Type. Same as IT (7).
11	Char1:	Character 1 with advantage/disadvantage at task.
12	Char2:	Character 2 with advantage/disadvantage at task.
13	String:	The string displayed to the player, often has %d's in it where
		values go.
